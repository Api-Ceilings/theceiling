Usage tiers

OpenAI has four usage tiers: Free, Build, Launch, and Grow. Each unlocks automatically when total credit purchases cross $5, $100, and $500 respectively. Rate limits apply at the organization level, not per user, and some model families share a single rate-limit pool — all calls to any model in a shared pool count toward the same TPM ceiling.

Rate limits by tier (standard)

On the Build tier, OpenAI allows 5,000 requests per minute and 1,000,000 tokens per minute for Astra, Sol, and Terra, or 2,000,000 TPM for Luna. Launch raises those to 10,000 RPM / 4,000,000 TPM (or 10,000 RPM / 10,000,000 TPM for Luna). Grow goes to 15,000 RPM / 40,000,000 TPM, and 30,000 RPM / 180,000,000 TPM for Luna respectively.

What a 429 (and 503) looks like

OpenAI returns two distinct errors when you exceed a limit. A 429 with code: slow_down means your request rate increased too quickly, even within the RPM and TPM ceiling — it is about rate of increase, not the absolute limit. A 503 with code: server_is_overloaded means the model itself is temporarily saturated on OpenAI's side.

Rule of thumb: once your traffic reaches 1 million input TPM, increase it by no more than 50% every 15 minutes. Hitting 4,999 RPM in one second can trigger slow_down even if your ceiling is 5,000 RPM.

Headers on every response

Every OpenAI response includes headers showing your current headroom. x-ratelimit-limit-requests and x-ratelimit-remaining-requests track RPM, while x-ratelimit-limit-tokens and x-ratelimit-remaining-tokens track TPM. Retry-After appears only on 429 and 503, and gives the number of seconds to wait before the next attempt.

Retry logic (Python, with Retry-After)

The correct retry behaviour is to read Retry-After and wait exactly that long, falling back to exponential backoff with jitter only when the header is absent. OpenAI's own documentation notes that their fallback examples do not inspect Retry-After — which is why many retry implementations hammer the API harder than necessary. Unsuccessful requests still count against your per-minute limit.

import time, random
from openai import OpenAI, RateLimitError, InternalServerError

client = OpenAI()

def call_with_retry(prompt, max_attempts=5, max_total_seconds=120):
    start = time.time()
    for attempt in range(max_attempts):
        if time.time() - start > max_total_seconds:
            raise TimeoutError("retry budget exhausted")
        try:
            return client.chat.completions.create(
                model="gpt-5.5",
                messages=[{"role": "user", "content": prompt}],
            )
        except (RateLimitError, InternalServerError) as e:
            if attempt == max_attempts - 1:
                raise
            retry_after = None
            if getattr(e, "response", None) is not None:
                retry_after = e.response.headers.get("retry-after")
            if retry_after:
                wait = float(retry_after)
            else:
                wait = (2 ** attempt) + random.uniform(0, 1)
            time.sleep(wait)

Escape hatch

Three escape hatches work when you are stuck on OpenAI rate limits. The Batch API does not count against synchronous RPM or TPM limits and is ideal for jobs that don't need a real-time response. Reducing max_tokens lowers effective TPM usage, because effective TPM is the greater of max_tokens or estimated prompt tokens. Upgrading tiers by crossing spend thresholds unlocks higher limits automatically.

  • Batch API — doesn't count against your synchronous RPM/TPM. Queue limits are based on total input tokens queued for a given model.
  • Reduce max_tokens — set it close to your actual expected output. Effective TPM is the max of max_tokens and estimated prompt tokens.
  • Upgrade tier — Build → Launch → Grow. Each threshold ($5, $100, $500 in total credits) unlocks higher limits automatically.
