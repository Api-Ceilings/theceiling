Discord is the first API on this site where the retry is the failure. A 429 counts as an invalid request, and 10,000 of them in 10 minutes gets your IP banned by Cloudflare — after which every call returns an HTML error page instead of JSON.

Three failure modes, three different fixes

The inversion. Seven pages on this site teach "on 429, wait and retry." On Discord that advice manufactures the ban. A tight retry loop on exhausted buckets generates 429s at machine speed, every one of which is an invalid request. 10,000 in 10 minutes — a sustained 16 to 17 requests per second — and Cloudflare bans the IP. A dead token retried overnight does the same thing with 401s.

Discord tells you not to hardcode limits. The docs state plainly that "rate limits should not be hard coded into your app" and that bucket sizes are intentionally unpublished. There is no table you can copy. The X-RateLimit-Bucket header is how you discover which routes share a budget — the first request to each route teaches you the map, and the map is the only source of truth.

Note the Retry-After header says 65 while the body says 64.57 — the header is rounded to whole seconds, the body carries millisecond precision. The optional code field appears for resource-specific limits such as 20016 (slowmode).

A reconnect loop that ignores 4008 / 4011 / 4014 drains the daily identify budget and locks the bot out until the window resets. Gateway heartbeats count toward the 120-event budget.

Retry logic that does not get you banned

import time, httpx

BUCKETS = {}           # bucket id -> monotonic reset time
INVALID = []           # timestamps of 401/403/429 (shared scope excluded)
SAFE_LIMIT = 9500      # margin under Discord's 10,000 / 10 min

def invalid_count():
    now = time.monotonic()
    while INVALID and now - INVALID[0] > 600:
        INVALID.pop(0)
    return len(INVALID)

def discord_call(client, method, path, token, **kw):
    url = f"https://discord.com/api/v10{path}"

    for attempt in range(4):
        if invalid_count() >= SAFE_LIMIT:
            # Stop before Cloudflare bans the IP. This is the whole point.
            raise RuntimeError("invalid-request budget nearly exhausted")

        r = client.request(method, url,
                           headers={"Authorization": f"Bot {token}"},
                           timeout=30, **kw)

        if r.status_code < 300:
            b = r.headers.get("x-ratelimit-bucket")
            if b:
                BUCKETS[b] = time.monotonic() + float(
                    r.headers.get("x-ratelimit-reset-after", 0))
            return r

        if r.status_code == 429:
            scope = r.headers.get("x-ratelimit-scope", "user")
            if scope != "shared":           # shared 429s are exempt
                INVALID.append(time.monotonic())
            body = r.json()
            time.sleep(float(body.get("retry_after", 1)))
            continue

        if r.status_code in (401, 403):
            INVALID.append(time.monotonic())
            r.raise_for_status()            # a dead token never recovers

        r.raise_for_status()

    raise RuntimeError("retries exhausted")

Three behaviours matter: (1) a local budget check that refuses new work before the ban, (2) shared-scope 429s excluded from that budget, (3) 401 and 403 never retried. The SDK and library ecosystems implement the same three things — Discord does not ship an official client that hides them.

One escape hatch

Read the bucket map instead of guessing it. Every other page on this site gives you a number to compare against. Discord gives you a header. Cache X-RateLimit-Bucket → X-RateLimit-Reset-After on every response, and treat the map as the ceiling definition: a route is safe when its bucket's reset has passed and its Remaining is above zero. That converts an unpublished limit into a locally known one after a single request per route. The corollary is that you must never synthesise a route key from a guess — use the real path with real IDs, because channel_id splits the bucket and a wrong key silently paces two unrelated routes as one.
